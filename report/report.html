Student Course Management System

Mid-Semester Lab Assessment — Project Report

Date: October 2026

1. What the System Does

The Student Course Management System is a browser-based application that helps students record and manage the courses they are taking for the semester. It is built entirely with HTML, CSS, and JavaScript — no external frameworks or server-side setup is required. Users simply open the index.html file in any modern web browser to run the program.

The system provides the following seven operations through a graphical menu interface:

# Operation Description
1 Add Course Enter a course code, title, and credit units to register a new course.
2 View All Courses Display every registered course in a formatted table.
3 Search Course by Code Find a specific course by entering its code.
4 Compute Total Units Calculate and display the sum of all credit units.
5 Save to File Download the course list as a .txt file.
6 Load from File Upload a previously saved .txt file to restore courses.
7 Exit Program Display a goodbye message; the user can then close the tab.

All data is also persisted in the browser's localStorage, so courses survive page refreshes without needing to manually save and reload a file.

2. How Each Major Feature Works

2.1   Add Course

The user fills in three fields — Course Code, Course Title, and Credit Units — and clicks "Add Course". The system validates every input: empty fields are rejected, units must be a positive integer, and duplicate course codes are not allowed. On success, a green confirmation message is displayed and the form is cleared for the next entry.

2.2   View All Courses

Clicking "View All Courses" renders every registered course inside a table with columns for row number, code, title, units, and a Remove button. The table is rebuilt (using a loop over the internal array) every time the view is opened, ensuring it always reflects the latest data.

2.3   Search Course by Code

The user types a course code and clicks "Search". Internally, the system uses a recursive search function (searchByCode) that starts at index 0, checks the current element, and calls itself with index + 1 until a match is found or the end of the array is reached. The result is shown in a highlighted card — green if found, red if not.

2.4   Compute Total Units

This feature uses a second recursive function (computeTotalUnits) that accumulates the credit units of each course by adding the current course's units to the result of calling itself on the remaining courses. The base case returns 0 when the index exceeds the array length. The total is presented in a large statistics card along with the course count.

2.5   Save to File

The system serializes every course into a CSV-formatted string (one line per course: CODE,Title,Units) with a header row. A Blob object is created from the string and offered to the user as a downloadable my_courses.txt file — no server is required.

2.6   Load from File

The user selects a previously saved .txt file. The system reads it using the browser's FileReader API, parses each CSV line back into a Course object (via Course.fromCSV), skips duplicates, and adds valid entries to the internal list. Any malformed lines are caught by try-catch blocks and reported as errors.

2.7   Exit Program

Selecting "Exit Program" displays a farewell message instructing the user to close the browser tab. Since data is saved to localStorage, nothing is lost.

3. Challenges Encountered & How Errors Were Handled

Several challenges arose during development, each addressed with deliberate error-handling strategies:

  • Invalid user input: Users might leave fields empty, type letters for units, or enter a negative number. Every input is validated inside addCourse() before a Course object is created. If validation fails, an Error is thrown and caught by a try-catch block in the UI layer, which displays a clear red error message — the application never crashes.
  • Duplicate course codes: Before adding a course, the system iterates through the existing array (using a for loop) to check if the code already exists. Duplicates are rejected with a descriptive message.
  • Corrupted or malformed files: When loading from a file, each line is individually parsed inside a try-catch. Lines that do not conform to the expected CODE,Title,Units format are skipped and their errors are collected. If no valid courses are found at all, the user is informed.
  • Data persistence across refreshes: Initially, refreshing the page cleared all courses. This was solved by adding localStorage persistence — courses are automatically saved after every add, remove, or file-load operation and restored when the page loads.
  • localStorage unavailability: In rare cases (e.g., private browsing), localStorage may not be available. The saveToStorage() and loadFromStorage() methods are wrapped in try-catch blocks so the application gracefully degrades — it still works, just without persistence.

4. Where Recursion Was Applied

Recursion is used in two core methods of the CourseManager class:

4.1   Recursive Search — searchByCode(code, index)

Instead of a simple loop, the search function calls itself with an incremented index until it either finds a matching course code or reaches the end of the array (base case). 

searchByCode(code, index = 0) {
    if (index >= this.courses.length) return null;          // base case
    if (this.courses[index].code === code.toUpperCase())
        return this.courses[index];                         // match found
    return this.searchByCode(code, index + 1);              // recursive call
}

4.2   Recursive Unit Computation — computeTotalUnits(index)

The total credit-unit count is calculated by recursively adding the current course's units to the result of calling itself on the rest of the array. 

computeTotalUnits(index = 0) {
    if (index >= this.courses.length) return 0;             // base case
    return this.courses[index].unit
         + this.computeTotalUnits(index + 1);               // recursive call
}

Both functions follow the standard recursive pattern: a base case that terminates the recursion, and a recursive case that reduces the problem size by one on each call.

5. Program Design Summary

The codebase is organized into three source files with three JavaScript classes:

File Purpose
index.html Page structure — header, menu, 7 content views, footer.
style.css Dark-themed styling, responsive layout, animations.
app.js All application logic — 3 classes described below.
Class Responsibility
Course Represents a single course. Handles string processing (trim, toUpperCase) and CSV serialisation/deserialisation.
CourseManager Manages the course array. Provides add, remove, search (recursive), compute units (recursive), save, load, and localStorage persistence.
AppController Connects the UI to the data layer. Handles DOM events, view switching, table rendering, and user feedback messages.
